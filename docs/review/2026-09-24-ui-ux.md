# UI and UX review, 2026-09-24

**Status:** parked until the architecture groundwork (ADR-0002 Phase 0) is done. Phase 1 items are
agreed. The "Brainstorm" list needs a conversation, and a mock-up, before Phase 2 code.
**Roadmap:** [ADR-0002](../adr/0002-review-roadmap.md), Phases 1, 2, and 4.

## How this was reviewed

Screenshots of the release build (no debug readout) at 1440 × 900, 1280 × 720, and a Pixel 7:
title, How to fly, mid-fight, spooling, the upgrade pick with a card open, and pause.

## Findings

### 1. The desktop is a phone emulator

The run column is `(100dvh − 240px) × 324 / 480` wide (`src/presentation/App.vue`). On 1440 × 900
that is about 440 px, and roughly 70% of the screen is empty black. PRD 12.6 already plans to use
the side margins.

### 2. Mixed pixel densities

- Ships are drawn at 64 × 64 (Raider 48 × 48) and shrunk 4× with nearest-neighbour, which keeps
  one pixel in sixteen. The detail in the files never reaches the screen.
- The desktop lane adds a 1.25 fighter scale, which cannot land on whole pixels.
- The canvas is scaled to fit, not by whole numbers, so on desktop the world pixels are uneven.
- The countdown is canvas text, and the HUD is crisp DOM text in a system monospace font.

Uniform pixel size is the strongest single signal that a pixel game looks right. The fix for the
sprites is a consistent density: two art pixels per world unit, decided 2026-09-24 ([ART-SCALE.md](../art/ART-SCALE.md)).

### 3. The visual hierarchy is upside down

The loudest element is the 84-pixel countdown painted in the playfield, in the bottom third where
the Viper flies. The Viper and the "Drag anywhere to fly" hint both land on top of it. The fighters
are about 20 CSS pixels tall on a desktop.

### 4. Buttons in the wrong place

The Missile and Speech buttons show on desktop, where the keyboard does the job. On a phone they
sit on the fleet line and hide the outer civilian hulls.

### 5. Text tells exist only in the debug readout

`loop` / `offline`, `bays` / `sealed`, `ejected`, `hull n/max`, `two transponders`, `raptor`, and
`six` render inside the debug readout (`src/presentation/components/HudBar.vue`), which a release
build hides. The PRD lists them as live, and "colour is never the only cue" depends on them.
**Owner decision:** this is a bug.

### 6. Two layouts

The title spreads three columns across the whole window, then a run snaps to the narrow column.
Launching feels like switching apps.

### 7. The pick sheet reads like a settings list

Three text rows with no rarity, stack count, icon, or card shape. It works on a phone and it is
readable, but it does not feel like a reward. The open row (effect plus Baltar and Roslin with
portraits) is good.

### 8. Smaller things

- No design tokens: 115 hard-coded hex colours in the Vue files and no CSS custom properties.
- No pixel font, although PRD 14 calls for one plus a readable-font toggle.
- The reduced-effects toggle applies only after a reload.
- `TitleOverlay.vue` is 646 lines.

## Phase 1: agreed quick wins

1. Design tokens for colour, spacing, and type.
2. A self-hosted pixel font (OFL) plus the readable-font toggle. Candidates in ART-DIRECTION 5:
   Silkscreen or Press Start 2P, and Atkinson Hyperlegible for the toggle.
3. The text tells in the shipped HUD (finding 5).
4. Missile and Speech only for touch (`pointer: coarse`), and never on the fleet line.
5. The countdown moves out of the playfield into the HUD. It stays visible while playing
   (owner decision 2).
6. An objective line that changes with the stage of the run.
7. Reduced effects applies without a reload.

## Proposed direction for Phase 2: Galactica's CIC

A suggestion to mock up, not a decision.

- **Desktop:** the lane stays portrait in the centre, framed as the Dradis plot. The margins become
  CIC consoles.
  - Left, FLEET: integrity, the FTL spool ring with Gaeta and Dualla, the civilian ship list with
    silly names (PRD 7.4), and the objective.
  - Right, COMMS: portraits at 128 CSS pixels (PRD 12.6), the comms log (PRD 12.2), and the loadout
    as small cards.
- **Phone:** the same modules collapse into a top strip (fleet, FTL, objective) and a bottom strip
  (comms, with the thumb buttons beside it).
- **Title:** the same shell with the consoles powered down. Launch powers them up. One layout.
- **Visual language:** one pixel font, tokens, stencilled panel labels (DRADIS, COMMS, FTL),
  phosphor green and amber, and red only for Cylons.
- **Upgrade cards:** a rarity frame, stack pips, an icon, and the joke up front. The effect and the
  two advisors stay one tap away.

## Brainstorm (settle before Phase 2 code)

1. **Integer scaling.** *Decided 2026-09-24: two art pixels per world unit, stretched to fit ([ART-SCALE.md](../art/ART-SCALE.md)).* The world is 480 tall. On a 900-pixel window only 1× fits whole, which is
   small. Options: scale to fit and accept uneven pixels; draw at a whole multiple into an
   offscreen target and then scale that smoothly; or change the world size. Each has a cost.
2. **One fighter size for both screens.** *Decided 2026-09-24: one size; the desktop boost goes away.* The native-scale redraw assumes the 1.25 desktop fighter
   scale goes away. That changes desktop hitboxes (PRD decision 14) and needs a fairness look.
3. **Where the countdown lands.** An FTL ring in the HUD, a bar across the top of the lane, or a
   quiet border that fills (PRD 5.1's "late-cycle border tell")? It must be glanceable without
   looking away from the Viper for long.
4. **How much of the CIC fits a laptop.** At 1280 × 720 there is less margin. Which console
   collapses first?
5. **The comms strip on desktop.** Does the bottom strip stay, or does comms move entirely to the
   right console?
6. **The title.** Does it keep How to fly and Credits as sheets, or become part of the consoles?
7. **The phone playfield after Phase 1.** The taller top band (clock, status, objective) costs the
   phone playfield some height, and the 9:16 canvas now letterboxes a few percent on each side. The
   CIC strips should win that back, for example by folding the objective into the status row.
8. *Deferred until after Phase 4 (2026-09-24), listed in ADR-0002.* **Scanlines and CRT** (PRD 14): on by default on desktop, off on phones. In or out of this pass?
